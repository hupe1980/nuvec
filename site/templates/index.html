Everything MLX gives you, in idiomatic Rust

The programming model that made MLX the fastest way to do machine learning on a Mac — rebuilt on Rust's ownership, typed errors and thread safety.

💤

Lazy arrays, unified memory

Operations record a graph and return at once; reading a value evaluates exactly what it needs. CPU and GPU share memory, so nothing is ever copied between them.

🔁

Transforms that compose

grad, vjp, jvp, vmap, custom_function, checkpoint and compile nest in any order — higher derivatives, per-example gradients, fused kernels.

🔥

MLX's Metal kernels

Tiled GEMM with split-K, GEMV, 1- to 6-bit and 8-bit quantized products, flash-style attention, RMSNorm, RoPE, sort, scan and mixture-of-experts gather kernels — or your own kernel from source.

🤖

An LLM runtime included

Llama, Mistral and Qwen 2/3/3.5 — dense, hybrid Gated DeltaNet or mixture-of-experts — straight from mlx-community checkpoints, with samplers, speculative decoding and batched serving.

💾

Memory-mapped weights

Aligned safetensors files are memory-mapped and wrapped as Metal buffers without a copy (mlx-community checkpoints are copied once at load), and stay resident through Metal residency sets while you generate.

🧪

Verified against MLX

Nearly a thousand recorded MLX results — random strides, offsets and dtypes, gradients and batching — replay on every test run, next to tiny reference models from mlx-lm.

How a computation runs

  1. 1Record

    Operations build a lazy graph; promotion, broadcasting and views are resolved up front.

  2. 2Transform

    grad, vmap and compile rewrite the graph — derivative rules, batching rules, fused kernels.

  3. 3Schedule

    A breadth-first order (MLX's) puts independent work side by side, ahead of time if you ask.

  4. 4Encode

    Metal kernels go into growing command buffers with minimal barriers, submitted asynchronously.

  5. 5Reuse

    Buffers are recycled while the GPU still runs, and updated in place when nothing else can see them.

Questions

Is nuvec a binding to MLX?

No. nuvec is written in Rust from the ground up and links no MLX or other C/C++ library. It reaches Metal through Apple's system frameworks and compiles its own Metal kernels, several of them ported from MLX.

How fast is it compared to MLX?

On an Apple M4 Pro (nuvec 0.4.0, 2026-10-23), nuvec-lm decodes at 0.99–1.10× the speed of mlx-lm across eight models from 0.6B to 35B parameters (geometric mean 1.02×), with the same time to first token (1.01× at 2,048 tokens). Concurrent serving is on par, and models load 1.6× faster. See benchmarks.

Which hardware does it support?

Macs with Apple Silicon (M1 or later) on macOS 15 or newer. The core and CPU crates also build and run on Linux.
